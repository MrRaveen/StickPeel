## 1. User flows

**Customer: new user**
- Land on the site → click Get started → go to sign-up in `app/`
- Sign up with email + password
- Either create an organization (you become owner) or join one through an invite link

**Owner / admin**
- Copy the invite link and share it
- Manage members and their roles
- Manage org settings
- Create teams, add members, assign a team lead

**Member (weekly cycle)**
- Pick a week (Monday date)
- Option A: paste a brain dump → AI returns a pre-filled draft → edit it in the form → save
- Option B: write the plan by hand (1 main task, sub-goals, go-to-market goals)
- Click AI review → see findings next to each task → apply a suggestion with one click, or ignore it
- Submit the plan
- During the week: tick tasks as done
- End of week: mark whether the main task shipped

**Team lead**
- See submitted plans
- Approve a plan, or send it back with a comment
- Pick a week → see all members: submitted, approved, tasks done, shipped or not
- Open the history view for past weeks

**Platform staff (internal panel)**
- Log in with a staff account (`is_admin`)
- Orgs: view the list, suspend or reinstate
- Users: search, see their orgs, deactivate
- AI usage: view calls, failures and rate-limited calls per org

## 2. Business flow

- Plan lifecycle: draft → submitted → approved → done
- Lead can send a submitted plan back with a comment, so the member edits and resubmits (the document doesn't name the "sent back" state; you decide how to model it)
- Goal of the week: ship one significant thing by Friday, nothing carried into Monday
- Good task = a checkable result, not work to do
- Every AI call is recorded against the org that made it
- Suspended org: members are locked out until reinstated
- Deactivated user: can't log in
- Staff run the platform, customers never reach the internal panel
- Founder side: define the customer, the pitch, the brand, and make every screen tell the same story

## 3. Business requirements

**Organizations and roles**
- Anyone can sign up with email + password only
- Roles: owner, admin, member
- Owners and admins manage members and settings
- Members plan their own weeks
- Invite link is enough (no email sending)

**Teams**
- Created by admins inside an org
- Members can be added; each team has a lead
- A user can be in more than one team

**Plans**
- One plan per member per week, keyed by Monday date
- 1 main task (with why it matters), a few sub-goals, go-to-market goals
- Go-to-market examples: analytics events, onboarding, changelog entry, landing page update, feature flag
- Each item is a separate task with its own status
- Lead approves or sends back with a comment
- Member marks if the main task shipped

**Team week and history**
- Lead sees all members at a glance for a chosen week
- History view for past weeks

**AI features**
- Plan review: flags tasks that are work not results, main task with no "why", missing go-to-market goals, scope too big for a week
- Each finding points at one task and has a suggested rewrite
- Brain dump → pre-filled draft, never saved straight to the DB
- The AI must do real work (it must not be replaceable by a textarea)

**Internal admin panel**
- Staff only, never created via sign-up
- Orgs: member count, team count, plan count, last active, suspend/reinstate
- Users: search, orgs per user, deactivate
- AI usage: calls, failures, rate-limited
- Clearly marked as internal
- Make a deliberate decision on whether staff see plan text

**Brand and landing page**
- One-line pitch, brand name (with a reason), logo SVG
- Logo works at 16px, on light and dark
- Hero, How it works, Show the AI, For teams
- Responsive, title, meta description, Open Graph image, no lorem ipsum
- Remove every "Launchbase" from user-facing places

**Seed data**
- `manage.py` command: 2+ orgs, a few teams, all roles, several weeks of plans (some shipped, some not)

**Out of scope**
- Billing, real email, email verification, password reset, SSO/social login, GitHub integration, notifications, deployment

## 4. Technical requirements

**Stack**
- Monorepo from Launchbase: `api/` (FastAPI, async SQLAlchemy, Postgres, Alembic, JWT, pytest), `app/`, `internal/`, `site/` (TanStack Start)
- API has two surfaces: `/app` and `/internal`
- Python 3.12 + uv, Node 24+, Postgres 16, Docker (tests start their own Postgres)
- Linux or macOS (WSL on Windows, repo under `~/`)

**Conventions (from AGENTS.md)**
- `uv run` for everything in Python
- Autogenerated Alembic migrations
- No enums in models
- Services flush, routers commit
- New resources follow the existing users resource
- Typed client via orval: `npm run generate`, no hand-written fetch
- Where the brief and AGENTS.md disagree, the brief wins (tests are required)

**Security and tenancy**
- All access rules enforced in the API, not the UI
- Org isolation on every query and every ID
- Role checks: member ≠ admin, non-lead can't approve
- Customer owner/admin can't reach `/internal`
- Staff tokens scoped to the internal surface
- Keep `is_admin` (staff) and org admin (customer role) clearly separate in naming
- Suspended orgs and deactivated users are blocked at the API

**AI integration**
- Pydantic AI + `gemini-3.5-flash-lite`: `uv add "pydantic-ai-slim[google]"`
- `output_type` is a Pydantic model (no JSON-in-prompt parsing)
- `GOOGLE_API_KEY` in `api/.env`, read through API settings; empty entry in `api/.env.example`; never in the browser or git
- App works if Gemini is slow, down or returns 429, with a plain message and no hang
- No request per keystroke
- Log every call: org, success or failure (rate-limited tracked separately)
- Loading state while the model runs

**Testing**
- `uv run pytest` passes with no key and no Google network
- Use `TestModel` / `FunctionModel`
- Cover agent code and tenancy rules, not only CRUD

**Frontend**
- Loading, empty and forbidden states; no dead buttons
- Brand carried through all three front ends

**Delivery**
- Commit in small steps
- `SUBMISSION.md` (run steps, demo logins for member / lead / owner / staff, name, pitch, name reason, real hours, what's not done)
- `git archive --format=zip -o assessment.zip HEAD`
- Unzip into a fresh folder and test before uploading
